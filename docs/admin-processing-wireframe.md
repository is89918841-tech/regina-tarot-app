# 관리자 처리 콘솔 와이어프레임 (텍스트 버전)

## 목표

관리자 페이지를 단순 조회 화면이 아닌, **접수 1건을 열어 추천 → 드로우 → 최종 리딩 → 전송 준비까지 한 화면에서 끝내는 작업 콘솔**로 설계한다.

---

## 1) 전체 레이아웃

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [상단 바] 검색 / 상태필터 / 새로고침 / 운영자 계정                           │
├──────────────────────┬───────────────────────────────────────────────────────┤
│ (A) 접수 목록 패널    │ (B) 선택 접수 상세 작업 패널                          │
│                      │                                                       │
│ - 필터 탭            │ 1. 접수 정보 카드 (상단 고정)                          │
│ - 목록 테이블        │ 2. 처리 상태 바 + 단계별 시각                          │
│                      │ 3. AI 추천 패널 (수정 가능)                            │
│                      │ 4. 자동 드로우 패널 (잠금 포함)                        │
│                      │ 5. 최종 리딩 생성 패널                                 │
│                      │ 6. 전송 준비 패널                                      │
└──────────────────────┴───────────────────────────────────────────────────────┘
```

- 기본 2단 구조:
  - 왼쪽(목록): 다건 운영
  - 오른쪽(작업): 단건 집중 처리
- 오른쪽은 세로 스택이며, **접수 정보 카드만 sticky 고정**한다.

---

## 2) 왼쪽: 접수 목록 패널

### 2-1. 필터
- `전체`
- `미결제`
- `결제완료`
- `추천완료`
- `리딩완료`

### 2-2. 목록 컬럼
- 접수번호
- 이름(또는 닉네임)
- 메뉴명
- 접수시각
- 결제상태
- 처리상태

### 2-3. 상태 색상 가이드
- `submitted`: 회색
- `paid`: 금색
- `recommended`: 파랑
- `drawn`: 보라
- `finalized`: 초록
- `sent`: 진초록(또는 남색)

### 2-4. 행 클릭 동작
- 클릭 시 우측 작업 패널에 해당 건 로드
- 현재 선택 행은 강조 표시

---

## 3) 오른쪽: 선택 접수 상세 작업 패널

## 블록 1. 접수 정보 카드 (상단 고정)

### 표시 항목
- 접수번호
- 이름/닉네임
- 연락 채널
- 메뉴명
- 금액
- 질문 원문
- 메모
- 접수 시각
- 결제 상태

### UX 규칙
- 카드 자체는 접히지 않음
- 질문 원문은 3~5줄 미리보기 + 전체보기

---

## 블록 2. 처리 상태 바

### 단계
`접수됨 → 결제확인 → 추천생성 → 자동드로우 → 최종리딩 → 전송준비`

### 표시 규칙
- 현재 단계: 강조
- 완료 단계: 체크 아이콘
- 각 단계 하단: 처리 시각 (없으면 `-`)

예시:
- 결제확인: `2026-04-18 14:21`
- 추천생성: `2026-04-18 14:24`

---

## 블록 3. AI 추천 패널

### 액션 버튼
- `추천 생성`
- `추천 다시 생성`

### 추천 필드 (운영자 수정 가능)
- 메인 덱 (select)
- 카드 장수 (number/select)
- 스프레드 이름 (select)
- 포지션 목록 (tag list)
- 보조도구 목록 (multi-select tag)
- 질문 주제 분류 (select)
- 추천 이유 (textarea)

### 예시 값
- 메인 덱: 로제딕 타로
- 카드 장수: 3장
- 스프레드: 핵심 정리 3카드
- 포지션: 현재 상황 / 고민의 핵심 / 조언
- 보조도구: 레노먼드, 귀문방
- 주제 분류: 연애/관계 판단
- 추천 이유: 감정 확인보다 흐름 정리와 선택 조언이 핵심

---

## 블록 4. 자동 드로우 패널

### 기본 입력 (추천값 자동 반영)
- 메인 덱: 자동 입력
- 장수: 자동 입력
- 스프레드 포지션: 자동 입력
- 역방향 허용: toggle
- 드로우 방식: `랜덤 / 숫자지정`
- 보조도구 사용: 체크 자동 반영

### 액션 버튼
- `추천값으로 자동 드로우`
- `다시 뽑기`
- `결과 잠금`

### 결과 표시 구조
- 덱
- 장수
- 포지션별 드로우
  - 카드 1
  - 카드 2
  - 카드 3
- 보조 결과
  - 레노먼드
  - 기타 보조도구 결과

### 잠금 규칙
- 잠금 전: 다시 뽑기 가능
- 잠금 후: 드로우 필드 read-only, 최종 리딩 생성 활성화

---

## 블록 5. 최종 리딩 생성 패널

### 입력 소스
- 질문 원문
- 추천값(수정본 포함)
- 실제 드로우 결과(잠금본)

### 액션 버튼
- `최종 리딩 생성`
- `문장 다시 생성`
- `수정 후 저장`
- `카톡용 짧은 버전 만들기`
- `복사`

### 저장 구조
- `finalReading`: 정식 리딩 본문
- `kakaoDraft`: 카톡 전송용 초안

---

## 블록 6. 전송 준비 패널

### 실무 버튼
- `카톡 보낼 문구 복사`
- `입금 확인 안내 복사`
- `리딩 완료 안내 복사`

### 카톡 자동 조합 예시
```
안녕하세요, 내담자님.
접수해주신 [메뉴명] 리딩 정리본 보내드려요.
[최종 리딩 본문]
```

---

## 5) 운영 UX 핵심 체크리스트

- 결제완료 건을 빠르게 처리할 수 있도록 기본 필터를 `결제완료`로 기억
- 추천값은 반드시 수동 수정 가능해야 함
- 드로우 결과는 `잠금` 전후 상태가 명확해야 함
- 최종 리딩은 본문/카톡 버전을 분리 저장
- 단계별 시각 로그로 병목 구간 추적 가능해야 함

---

## 6) 구현 순서 제안 (MVP)

1. 좌측 목록 + 상태 필터 + 우측 상세 로더
2. 접수 정보 카드 + 처리 상태 바
3. AI 추천 생성/수정 저장
4. 자동 드로우 + 결과 잠금
5. 최종 리딩 생성 + 2종 텍스트 저장
6. 전송 준비 복사 버튼 + 템플릿 관리
